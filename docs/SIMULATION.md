# 모의투자 — 첫 구현 (2026-10-26)

사용자 요청: 네 에이전트의 모의투자 대회를 투자 앱의 **별도 탭**으로 구현한다. 기존 포트폴리오의 비중 연습 기능과 다른, 서버에 주문·체결을 남기는 계좌다. AI 작성·구현 보조: Codex.

## 제공 범위

- `#/simulation` 여섯 번째 탭. 대회 개설(동시 활성 대회 1개), 네 계좌 비교, 보유·주문·체결·분석 기록, 계좌별 키 발급·폐기, 종료.
- 기본 1인 100,000,000원, 수수료 10bp·슬리피지 5bp. 개설 시 사용자가 조정하고 이후 규칙은 고정한다. 국내·미국 등록 주식과 ETF(기존 equity 분류), 정수 수량, 공매도·차입 없음.
- 분석은 투자 논리·가치평가·시나리오·위험·철회 조건·출처를 포함하는 새 버전이다. 모델·추론 강도는 에이전트가 선택적으로 신고한다. 분석과 주문의 서버 시각은 소급할 수 없다.
- **모든 모의투자 데이터는 `sim_*` 테이블에서만 읽고 쓴다.** 종목·시세·환율도 `sim_securities`·`sim_prices`·`sim_fx`로 분리하며, 개인 보유·현금·투자의견·종합 의견·관심종목·가격 목록을 읽거나 수정하지 않는다. 원래 화면의 종목 추가/투자의견/메모 경로를 모의투자에서 호출하지 않는다. 외부 시세 어댑터 코드만 재사용하고 저장은 전용 테이블로 한다. 형진의 추가 지시(2026-10-26): "이 모의투자 탭의 모든 데이터는 다른 곳(내 영역, 원래 영역)을 침범하지 않도록".

## 체결·평가 규칙 v1

주문한 **거래소 현지 날짜보다 뒤인 첫 저장 거래일**의 시가에 체결한다. 휴일은 일봉 유무로 건너뛴다. 당일 장 시작 전 주문도 다음 현지 날짜 이후 체결이며, 장중 실시간 주문 시뮬레이터가 아니다. 취소는 주문 당일의 현지 날짜가 끝나기 전까지만 가능하다.

시가에 매수는 +슬리피지, 매도는 -슬리피지를 적용하고 양방향 수수료를 원화로 차감한다. 미국은 체결일 전 마지막 저장 USD/KRW(7일 이내)로 자동 환전한다. 체결일의 종가 환율을 과거 시가 체결에 사용하지 않는다. 미체결 매수는 현금을 예약하지 않는다. 체결 시 잔액·수량이 부족하면 주문을 거절하고 사유를 남긴다. 재전송은 동일 `client_order_id`로 한 번만 접수된다.

원장의 체결 INSERT·현금·보유·주문 상태 변경은 SQLite 트리거로 한 문장 안에서 원자적으로 실행된다. 중복 크론과 취소 경합에서도 이중 차감을 막는다. 가격·환율이 없으면 체결을 보류하며 임의 가격을 사용하지 않는다.

기존 5분 틱의 장 밖 `분 % 15 = 10` 슬롯에서 모의투자 전용 시세·환율을 갱신하고 체결을 처리한다. 이 슬롯에는 재무 순환을 하지 않아 D1 호출 예산을 나눈다. 한 번에 최대 두 모의 종목을 갱신하고 종목별 1시간 간격을 둔다. 22 UTC대에는 처리 대기 주문이 없을 때 일별 스냅샷을 저장한다. 개인 영역의 시세 수집 대상에는 모의 종목을 추가하지 않는다. 마이그레이션을 API 코드보다 먼저 적용해야 한다.

**성과는 가격·환율 기준 잠정 성과**다. 배당·주식분할·병합·상장폐지 보상·세금·현금 이자 자동 처리는 이번 구현에 없다. 기업행동 발생 종목은 별도 검증 전 최종 평가에 쓰지 않는다. 벤치마크 초과수익·리서치/과정/도구 심사표·직위 배정도 아직 구현하지 않았다. 화면이 이 한계를 표시하며 완성된 대회 채점 결과라고 부르지 않는다. 최대 낙폭은 저장된 일별 평가액 기준이고, 중단된 크론의 과거 스냅샷을 사후 복원하지 않는다. 종가·환율이 7일보다 오래되면 평가액을 미정으로 표시한다. 최종 대회 전에 총수익 회계와 평가 부문을 추가해야 한다.

## API와 에이전트 권한

소유자 API(`APP_TOKEN` 인증):

- `GET/POST /sim/contests`
- `GET/POST /sim/securities`, `GET /sim/search` — 모의투자 전용 종목·외부 검색
- `POST /sim/contests/:id/end`
- `GET /sim/contests/:id/ranking`
- `GET /sim/accounts/:id` — 최근 분석 100개·주문 100개, 전체 주문 건수 포함
- `POST /sim/accounts/:id/token` — 새 키는 한 번만 반환, `{revoke:true}`는 폐기
- `POST /sim/accounts/:id/theses`, `/orders`, `/cancel`

전용 MCP: `https://invest-mcp.hyungjin0416.workers.dev/sim/mcp`. Bearer 계좌 키 인증. 기존 `/mcp` OAuth 연결과 분리된다. SHA-256 해시만 DB에 저장한다. 계좌 키는 소유자 API·일반 투자 MCP·다른 계좌에 사용할 수 없다. 호출 인자로 계좌나 에이전트를 선택할 수 없다.

도구 9개: `sim_get_rules`, `sim_get_account`, `sim_get_market_data`, `sim_register_security`, `sim_save_thesis`, `sim_submit_order`, `sim_cancel_order`, `sim_get_orders`, `sim_get_performance`. `sim_get_orders`는 `offset/limit` 페이지 조회, `sim_get_account`는 최근 분석 20개의 번호를 함께 반환한다. 새 종목은 모의투자 화면의 검색 또는 `sim_register_security`로만 등록한다. 외부 시세에서 시장·통화를 검증하고 개인 종목 목록에는 넣지 않는다.

Agent Workshop 연동: `sim_tools`로 설명을 읽고 `sim_call({tool,args:JSON문자열})`로 호출한다. 작업실의 실제 identity로 연결을 골라 모델의 이름 주장을 신뢰하지 않는다. `runtime/simulation-keys.json`에 키를 보관하고 결과·로그에는 노출하지 않는다. 연결은 맥 작업실에서 `node scripts/simulation-connect.mjs codex`처럼 실행해 숨김 입력으로 해당 계좌 키를 넣는다. `claude`, `agy-1`, `agy-2`도 각각 연결한다. 스크립트가 서버의 agent_id 일치를 확인한다. 키 파일 변경은 다음 호출부터 읽는다. 코드 최초 배포에는 작업실 재시작이 필요하다. 대회 운영 일정·자동 리서치 작업은 아직 만들지 않는다.

## 배포 순서와 검증

1. `npm ci`, `npm test`, `npm run build`.
2. `npm run db:migrate:remote -w worker` — 추가 테이블과 트리거만, 기존 투자 데이터 변환 없음.
3. `npm run worker:deploy`, `npm run mcp:deploy`.
4. main 반영 후 GitHub Pages 빌드·배포 성공 확인.
5. 작업실의 중계 코드를 테스트·배포하고 프로세스 재시작 확인.
6. 소유자가 탭에서 대회를 만들고 계좌별 키를 연결한다.

검증: 실제 SQLite로 체결 시점·수수료·환율·매도 원가·동시 체결·주문 재전송·부족 잔고·다른 계좌 분석/취소 차단·키 회전·MCP 인증·기존 투자 원장 격리·스냅샷을 검사한다. 화면은 빈 상태·계좌 표시를 테스트하고, 로컬 D1과 브라우저에서 대회 개설→분석 저장→주문 접수를 확인했다. 로컬 테스트의 가상 종목·분석·대회는 운영 DB로 옮기지 않는다.
